# Сборка и релиз

## Артефакты

| Платформа | Что | Файлы |
|---|---|---|
| Windows | `Parser.exe` + установщик | `parser.spec`, `build.bat`, `installer/windows.iss` |
| macOS | `.app` | `parser-mac.spec`, `build-mac.sh` |
| Тесты | CI | `.github/workflows/ci.yml` |

PyInstaller собирает **папку** (`onedir`) и кладёт рядом `static/`,
`templates/`, `.env.example`. `app.py` вызывает `freeze_support()` до всего
остального — иначе каждый дочерний процесс перезапускает приложение.

## Версия и обновления

- Версия хранится в `static/version.json` и штампуется
  `scripts/stamp_version.py`.
- Клиент проверяет обновления (`routes/update.py`), скачивает новый exe и
  подменяет его через `updater_helper.py`.
- Порог минимальной версии блокирует устаревшие сборки.
- Заметки об обновлении — `update_notes/notes/*.json`, окно «Что нового».

## GitHub Actions

- `build-exe.yml` — Windows-сборка;
- `build-macos.yml` — macOS;
- `build-manual.yml` — ручной запуск;
- `publish-release.yml` — публикация;
- `verify-release-assets.yml` — проверка вложений;
- `announce-release.yml` — анонс;
- `prune-releases.yml` — чистка старых;
- `ci.yml` — тесты.

## Правила релиза

- Перед сборкой — зелёные тесты и обновлённые заметки об изменениях.
- Артефакты (`dist/`, `build/`, `_update/`) в репозиторий не попадают.
- Пуш, тег и публикация — только по прямой просьбе пользователя.
- Иконки: `static/icon.ico` / `static/icon.icns`, генератор —
  `scripts/gen_icon.py`.
