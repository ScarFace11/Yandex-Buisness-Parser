# Тесты и проверки

## Быстрый минимум

```bash
./.venv/Scripts/python.exe -m pytest tests/test_ui_markup.py -q
node --test tests/ui/*.test.mjs
```

`node --test tests/ui/` с папкой на этой версии Node падает — нужен glob.

## Пирог проверок

| Что | Файлы | Когда нужен |
|---|---|---|
| Разметка и CSS | `tests/test_ui_markup*.py`, `test_theme_contrast.py` | правка HTML, стилей, текстов |
| Логика UI | `tests/ui/*.test.mjs` (Node, DOM-заглушка) | правка `static/js` |
| Парсер и данные | `tests/test_pipeline.py`, `test_exporters*`, `test_excel_columns.py`, `test_geocoding.py` | правка полей и выгрузки |
| API | `tests/test_public_api.py`, `test_api_keys.py`, `test_rate_limit.py` | правка маршрутов |
| Обновления и сборка | `test_updater_swap.py`, `test_macos_build.py`, `test_windows_installer.py` | релизные правки |
| Доступность | `test_a11y_browser.py`, `test_a11y_keyboard.py`, `a11y_audit.js` | клавиатура, фокус, контраст |

## Особенности

- Тесты читают **склеенные** модули JS (`tests/_appjs.py`) и части CSS
  (`tests/_css.py`, `tests/ui/_css.mjs`) в порядке каскада — как шаблон.
- `tests/ui` работает на самодельной DOM-заглушке: проверяют логику и
  тексты, а не реальную отрисовку.
- Аудит доступности (`scripts/a11y_watch.py`) следит за `static/css/*.css`,
  `static/js/*.js`, шаблоном и сам собой перезапускается.
- Стили и тексты проверяются точными строками: меняешь формулировку —
  обновляй тест и объясняй, почему новая лучше.

## Чего не делать

- Не ослаблять утверждения и не удалять тесты ради зелёного прогона.
- Не выдавать непроверенное за проверенное: браузерные тесты часто
  невозможно запустить — так и пиши в отчёте.
- Не запускать настоящий парсинг вместо теста: это живой запрос к Яндексу.
