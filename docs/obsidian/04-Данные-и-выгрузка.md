# Данные и выгрузка

## Поля записи

Общий список — `yandex_maps_parser/constants.py` → `CSV_FIELDS`. Именно он
определяет CSV, JSON и порядок колонок Excel; подписи — `HEADER_LABELS`.

| Поле | Что это |
|---|---|
| `reviewed` | отметка «Просмотрено» |
| `lead_score` | оценка 0–100 |
| `name`, `category`, `address`, `phone` | карточка организации |
| `rating`, `reviews_count` | рейтинг и число отзывов |
| `vk`, `instagram`, `telegram`, `whatsapp` | ссылки на соцсети |
| `vk_activity`, `vk_followers`, `vk_last_post_days` | активность ВК (при ключе) |
| `aggregator_url` | страница-агрегатор |
| `yandex_maps_url` | карточка на Картах |
| `query`, `parsed_at`, `city` | контекст поиска |
| `lat`, `lon` | координаты точки на карте |

**Координаты обязательны.** Вкладка «На карте» читает `lat/lon` прямо из
файла; если поле не записалось, карта пустая, хотя данные есть. Новое поле
добавляется одновременно в `CSV_FIELDS`, подписи Excel и тест на карту.

## Оценка лида

`lead_score.py`, сумма правил ровно 100 — ключ ВК для полной шкалы не нужен:

- нет сайта — 30;
- хороший рейтинг — 15;
- много отзывов — 15;
- есть телефон — 10;
- дорогая категория — 10;
- есть соцсети или мессенджер — 15.

Активность ВК баллов не даёт: раньше она добирала остаток до 100, и оценка
идеального лида без ключа упиралась в 90 — цифра зависела от настроек, а не
от клиента. Теперь состояние сообщества только справочная строка в разборе.
JS-зеркало — `SCORE_RULES` в `static/js/04-results-table.js`.

Критерия «новая организация» нет: дату добавления карточка не отдаёт,
поле `added_at` никто не заполняет — критерий не срабатывал ни разу, а в
разборе всегда стояло «Дата добавления — нет данных».

Пороги в интерфейсе: «горячий» — от 70, «тёплый» — от 45.

## Форматы

- **Excel (.xlsx)** — основной: колонки по `CSV_FIELDS`, ширины, шапка,
  отметки «Просмотрено» пишутся обратно в файл.
- **CSV** — те же поля, UTF-8 с BOM для Excel.
- **JSON** — полные записи; `_results_for_frontend.json` — внутренний
  объединённый файл для таблицы.
- **Карта (.html)** — автономная страница Leaflet с точками.

## Колонка «Сайт» в таблице

Ссылка на страницу клиента в файле — поле «Сайт / Таплинк»
(`aggregator_url`): при записи туда же попадает и своя страница организации
(`normalize_record`). Отдельная колонка «Сайт» в таблице результатов читает
именно это поле, показывает домен и держит полный адрес в подсказке;
сортировки у неё нет — порядок по домену в контракте сервера не заведён.
Колонка участвует в общем списке «Столбцы» и переставляется как остальные.

## Как читаются результаты

Этап 2 пишет один и тот же результат сразу в несколько форматов
(`processed/excel`, `processed/json`, `processed/csv`). Таблица
«Результаты» читает **один файл на результат** — JSON, иначе Excel,
иначе CSV. Иначе 156 организаций показывались как 312: Excel и JSON
считались двумя разными наборами. Файлы с разными именами (повторная
фильтрация) остаются оба — это действительно разные срезы.

Переключателя «Сырые / Обработанные» в таблице нет: после этапа 2 оба
среза совпадали. Таблица показывает итог обработки, а сырые файлы
по-прежнему лежат в `output/raw/` и открываются из «Истории файлов».

## Фильтры выгрузки

`apply_output_filters` и «Фильтрация результата» в интерфейсе:

- только без сайта;
- города и запросы;
- обязательные соцсети;
- минимальная оценка;
- только новые;
- объединение филиалов сетей.

Клиентская копия логики должна совпадать с серверной: таблица показывает
ровно то, что попадёт в файл.

## Геоданные

- Центр города — `city_coords.py` (офлайн-справочник) и `browser_search.city_center`;
- рамка города (`lookup_bbox`) обрезает сетку точек, чтобы круг не захватывал
  пригороды;
- координаты карточки — из атрибутов выдачи (`data-coordinates`);
- кэш геокодинга живёт в памяти прогона.
