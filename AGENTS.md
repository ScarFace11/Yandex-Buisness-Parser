# AGENTS.md — правила работы над «Поиском клиентов»

Файл для любого агента (и человека), который берётся за этот проект.
Сначала прочитай его целиком, потом — [карту проекта](docs/obsidian/00-Главная.md).

## 1. Правила, которые задал пользователь

1. **Коммить свою работу всегда, не спрашивая разрешения.** Один
   законченный шаг — один коммит. Не оставляй готовые правки в рабочей
   копии «на потом». **Пуш — только по прямой просьбе пользователя:**
   готовый коммит остаётся локальным, пока не прозвучит «пуш», «залей»
   или «выложи». Сам не отправляй в GitHub, не создавай PR и не запускай
   релиз.
2. **Разделяй технические и пользовательские кнопки.** В шапке — две
   визуальные группы: «Соглашение / Готово / Уведомления / тема» и
   служебные «Логи / Диагностика / Проблема / Что нового / Обновления».
   Не смешивай их в один ряд.
3. **Мелкий шрифт не опускается ниже 12px.** Подписи, сноски, счётчики —
   всё читаемое. Исключений «это же подпись» нет.
4. **Второстепенные панели свёрнуты по умолчанию** («Массовый обход» и
   подобные), чтобы таблица результатов была видна сразу.
5. **Координаты обязаны попадать в выгрузку** (CSV/Excel/JSON), иначе
   вкладка «На карте» остаётся пустой. Новые поля — только через общий
   список колонок и с тестом на карту.
6. **Единая сетка.** Отступы, зазоры и вертикали берутся из токенов
   проекта; «на глаз» не двигаем. Текст не должен «плыть» относительно
   соседних блоков.
7. **Тексты — простым языком, без жаргона.** В интерфейсе нет «парсера»,
   «эндпоинтов» и «раннеров»: есть «поиск», «результаты», «файлы».
8. **Пустые экраны объясняют следующий шаг**, а не констатируют пустоту:
   что появится и куда нажать.
9. **Длинный текст сворачивается.** Сначала одна короткая строка, подробности
   — по нажатию или в подсказке при наведении.
10. **Разделы должны читаться без напряжения.** Маленькая полоска — не
    разделитель: у блока есть заголовок, ритм и граница.
11. **Оценивай интерфейс как обычный пользователь.** В отзывах — простые
    слова, без технического жаргона; описывай момент, в который возникла
    проблема, и что почувствовал.
12. **Исправляй по шагам и по пунктам.** Сначала первый пункт ревью, потом
    второй. Можно задавать вопросы, если выбор меняет объём работы.
13. **Всегда обновляй тесты вместе с поведением** и не ослабляй проверки
    ради зелёного прогона.
14. **Документация проекта живёт в Obsidian-хранилище** `docs/obsidian/`.
    Меняешь архитектуру или правила — обнови заметку.
15. **Каждое изменение записывается в историю** `CHANGELOG.md`. Закончил
    шаг — допиши понятную пользователю строку (что стало удобнее или что
    починили) в раздел текущей версии, свежее — сверху. Изменение и его
    строка в истории — один коммит: коммит без записи считается недоделанным.

## 2. Правила, которые стоит соблюдать дополнительно

### Git
- Префиксы коммитов: `feat`, `fix`, `style`, `refactor`, `test`, `docs`,
  `chore`. Заголовок — по-русски, до ~72 символов.
- В том же коммите — строка в `CHANGELOG.md`: история для пользователя
  обновляется вместе с кодом, а не «потом», иначе часть правок теряется.
- В теле коммита — **почему** изменение нужно, а не пересказ диффа.
- Завершай коммит футером Codebuff (`Generated with Codebuff` +
  `Co-Authored-By`), если пользователь не попросил обратного.
- Коммит и пуш — разные шаги: коммит делается всегда, пуш — только
  когда пользователь прямо попросил. Деплой, релиз и PR — тоже только по
  просьбе.
- Не стейджи чужие правки: `git add` — только свои файлы, без `-A`.
- Сгенерированные артефакты (`output/`, `logs/`, `screenshots/ui-*.png`,
  `_update/`, `dist/`) в коммит не попадают.

### Код и стиль
- Python — Flask, без ORM; на Windows запуск через
  `./.venv/Scripts/python.exe`, синтаксис shell — bash (Git Bash).
- Фронтенд — чистый JS без сборщика. Модули `static/js/01-…13-…`
  подключаются по порядку; порядок важен, тесты склеивают их так же
  (`tests/_appjs.py`).
- Стили — части `static/css/00-…20-…`. **Порядок подключения — это каскад**
  (см. `static/css/README.md`). Новое правило кладётся в часть своего
  блока; перекрывающее — только в ту же или более позднюю часть.
- Комментарии — по-русски и только там, где объясняют причину: «почему
  так, а не иначе». Не пересказывай код.
- Хардкод цветов запрещён: только токены темы (`var(--…)`).
- Интерактивные элементы — не меньше 24×24 px по площади нажатия
  (сам чип может остаться компактным, зона — нет).
- Любая иконка-кнопка имеет `aria-label`; фокус видим в обеих темах.
- Новые поля формы сопровождаются подписью (`<label for>`), а не только
  `placeholder`.

### Проверки
Минимум перед коммитом:
```bash
./.venv/Scripts/python.exe -m pytest tests/test_ui_markup.py -q
node --test tests/ui/*.test.mjs          # именно glob: папку Node не принимает
```
Если менялись данные/выгрузка — дополнительно профильный тест
(`tests/test_excel_columns.py`, `tests/test_geocoding.py`,
`tests/test_results_files.py`). Браузерные `tests/test_a11y_browser.py`
и `tests/test_a11y_keyboard.py` запускаются, когда правка касается
клавиатуры или контраста; если не запускались — так и напиши в отчёте.
Никогда не выдавай непроверенное за проверенное.

### Интерфейс
- Сначала — что человек хочет сделать; служебное — ниже и компактнее.
- Неактивная кнопка объясняет причину рядом с собой, а не чипом наверху
  длинной панели.
- Одна управляющая кнопка запуска: «Найти» → «Пауза» → «Продолжить».
- Док запуска не перекрывает поля: непрозрачная подложка + шов, контент
  уходит под него.
- Закрытый аккордеон не показывает обрезанную первую строку.
- Тексты в интерфейсе проверяются тестами на точные строки: меняешь
  формулировку — обнови тест и объясни, почему формулировка лучше.

### Данные и безопасность
- Не запускай настоящий парсинг «для проверки», если хватает тестов:
  это живой запрос к Яндекс.Картам и время пользователя.
- Не трогай `output/`, `logs/` и `settings.json` без необходимости.
- Ключи и токены — только в `.env`, в код, логи и коммиты не попадают.
- Пользовательские пути и имена файлов экранируются (`escapeHtml`,
  `encodeURIComponent`).

### Документация
- `docs/obsidian/` — карта проекта для чтения: архитектура, поток данных,
  интерфейс, тесты, релиз, глоссарий.
- Обновил схему выгрузки — обнови `docs/obsidian/04-Данные-и-выгрузка.md`.
- Добавил часть CSS или JS-модуль — обнови соответствующую заметку и
  `static/css/README.md`.

## 3. Быстрый старт

```bash
# приложение (локально, без открытия браузера)
YP_PORT=5014 YP_OPEN_BROWSER=0 ./.venv/Scripts/python.exe app.py

# тесты интерфейса
./.venv/Scripts/python.exe -m pytest tests/test_ui_markup.py -q
node --test tests/ui/*.test.mjs

# где что лежит
docs/obsidian/00-Главная.md
```
